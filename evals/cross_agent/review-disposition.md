# Independent review disposition

## Codex server review

Source: [saved review](codex-review.txt), generated by Codex CLI 0.160.1 in a read-only session. All five concrete findings were accepted and fixed:

| Finding | Change | Regression check |
| --- | --- | --- |
| Mixed quoted/unquoted duplicate statuses admitted ambiguous approval | Count all status keys before validating the single supported scalar | Duplicate `approved` / quoted `draft` frontmatter is excluded |
| Multi-ID questions required all IDs inside one section | Retrieve the union of matching REQ sections | Two separately documented IDs return two evidence records |
| Stale top-ranked result hid live lower-ranked evidence | Validate ranked results before applying the output limit | Superseded first hit is skipped and the live replacement fills limit=1 |
| CLI search omitted corpus ownership validation | Validate meta.root in the shared database context | Reusing an index for another PRD_DIR raises an error |
| Synchronous dispatch blocked MCP event loop on flock waits | Run index work with asyncio.to_thread in async MCP endpoints | Actual stdio calls pass; shared locking remains bounded |

Additional local finding: citations originally named corpus-relative files, which a client could mistakenly link at the repo root. Returned sources now resolve relative to the checkout (`prds/auth.md`) or use an absolute path for external corpora. Targeted Codex citation checks were rerun successfully.

Rejected Codex findings: none. The review did not demonstrate downstream execution of malicious PRD text; no claim of prompt-injection immunity is made.

## Cursor adapter review

Research-based and code-only review attempts initially hit the 180-second per-agent timeout without a final verdict. The final code-only attempt completed within the 600-second deadline and produced [five findings](cursor-review.txt).

| Finding | Disposition |
| --- | --- |
| Cursor prompt pointers should be returned in user_message | Rejected as a delivery fix: current docs describe user_message as the message shown when a prompt is blocked. Returning it on an allowed prompt does not establish model-context delivery. Diagnostic-only behavior remains explicit. |
| Cursor approved edit warning is not delivered through the allow response | Accepted as a documented platform limitation; rejected blocking the edit merely to deliver a warning. agent_message is documented on denial, and these hooks must fail open. The alwaysApply/shared instructions carry the authoring policy. |
| Startup import/context/argv failures occur outside the handler | Fixed: PRD imports and context reads now occur inside guarded execution; missing/invalid argv also fails open. Missing SDK/CLI was already caught because the SDK is not imported for hook startup. |
| Atomic rename does not protect hook-state read/modify/write | Fixed: shared file-lock implementation guards session-state updates; prompt hooks use a short lock deadline to preserve latency. Busy hooks fail open. |
| Generator assertions disappear under -O | Fixed: explicit ValueError validation runs in optimized Python too. |

No independent reviewer asserted the final fixes were re-reviewed. Runnable local regression checks verify the accepted changes; the saved review describes the pre-fix code.

Local verification separately caught and fixed the CLI permissions schema's required deny array, shell assignment quoting for paths containing spaces, and portable drift comparison across checkout paths with different quoting requirements. No broad permission bypass was used. Cursor's documented output limits remain explicit in README: prompt pointers and allowed-edit warnings are diagnostics, not equivalent context injection.
